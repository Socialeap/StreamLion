## Product limits and unfinished planned features

The first release supports one provider, one verified commissioning client, one primary site, and explicit appointment/fee/delivery agreement. Provider-reported payment is labelled; bank reconciliation is not connected. Clients never trigger AI spend. Only fully verified mutual agreement activates the one-time project charge.

The committed pilot limits remain: 100 open requests per workbook, a 10,000-total-grid-row/tab adapter ceiling, 512 KiB PDF/JPEG/PNG uploads with at most 20 attachments per job, and a bounded encrypted archive. These are safety limits, not proven throughput or storage guarantees.

Provider-versioned service/intake templates and conditional questions from PR #65 are deployed, with saved versions pinned to requests and required answers enforced during agreement. Actual authorized Google/client acceptance is recorded above. [Template behavior](service-intake-templates.md). PR #64's client-link recovery fixes are also deployed; physical installed-app update/reopening acceptance is separate.

The signed version 2 archive/recovery implementation from PR #66 is deployed. It verifies exact original files, gates both workbooks during recovery and retains the original workbook/files. Reasoned **Archive now** ends access without changing production clocks. Actual Google archive/restore/reopen acceptance is recorded above; accepted Core/observation import also passed with fresh Google readback and source retention, while device download remains separate. [Archive behavior](archive-recovery.md).

Linked multi-location requests and agency roles are later increments under the MVP spec. Automatic destructive archive compaction and an installed operator dashboard remain unfinished. PR #67 provides a private manual operations/cost report; PR #68 fixes its actual production D1 compatibility. Rollover retains original books/files and bounds the new active workbook; it does not shrink or silently clear old history. Retained history is never deleted to make a capacity test pass. Their intended release scope must stay visible; no public page should advertise an undeployed or unverified capability as delivered.
