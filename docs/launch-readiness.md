## Capacity and product limits

- Sheets/Drive remain the record store. Cloudflare stores encrypted authorization and counters, not a project database. Ordinary ChatGPT uses a user-copied dated snapshot; there is no owner-funded model API.
- The persistent proxy reserves separate read/write capacity at 200 requests per project per fixed UTC minute and 40 per account. These conservative application limits are below Google's documented default Sheets quotas. Window boundaries and other clients can still cause an upstream 429; bounded reads respect `Retry-After`, while writes retain their pending operation for explicit verification/retry.
- A user interaction can require several Google requests; these figures are not simultaneous-user capacity or a promise of unlimited scale. Writes also consume D1 capacity. The existing D1 Free account has hard allowances; no paid upgrade or auto-recharge is authorized.
- Each workbook tab is limited to a grid height of 10,000 rows, with append blocked at 10,000 populated rows. Rows include revision history. No automated journal archival/compaction exists; larger workbooks need a reviewed archival design before raising the limit.
- Same-browser write locks serialize tabs, and revision readback detects conflicting children. Sheets has no transactional compare-and-swap across devices. Use one active editor per project for the initial release; multi-device collaboration at scale remains a design/test gate.
- Device backups are private, unencrypted JSON with SHA-256 corruption checks; they are not signed files. Maximum backup size is 100 MiB; individual retained files follow the existing 5 MiB attachment limit. Browser storage can be evicted, so backups remain necessary.
- OAuth starts are limited to 60 per project / 5 per network address per fixed minute, callbacks to 120 / 10. Only a keyed hash of Cloudflare's network-address header is stored; missing headers share a conservative fallback bucket. Production quota monitoring, abuse review and a representative multi-account capacity exercise remain required before a broad launch. No real-user load test or paid provider calls were run.

## Activation and rollback

Follow [persistent-google-activation.md](persistent-google-activation.md) for exact migration preflights, minimum deployment, secrets, receipt and owner acceptance. Use the approved full main SHA with `scripts/verify-release.mjs`. Enable persistent mode last. If acceptance fails, turn the flag off and redeploy the last approved Pages release; preserve the D1 vault, device drafts and Google records. Do not rotate the encryption key as a troubleshooting shortcut.

No Lovable action is required. StreamLion's release systems are GitHub, Cloudflare and Google Cloud. Code readiness, live activation, device QA and public-sale approval are separate gates.
