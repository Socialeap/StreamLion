## Product limits and unfinished planned features

The first release supports one provider, one verified commissioning client, one primary site, and explicit appointment/fee/delivery agreement. Provider-reported payment is labelled; bank reconciliation is not connected. Clients never trigger AI spend. Only fully verified mutual agreement activates the one-time project charge.

The committed pilot limits remain: 100 open requests per workbook, a 10,000-total-grid-row/tab adapter ceiling, 512 KiB PDF/JPEG/PNG uploads with at most 20 attachments per job, and a bounded encrypted archive. These are safety limits, not proven throughput or storage guarantees.

Provider-versioned service/intake templates, service-dependent dynamic questions and linked multi-location requests are still unfinished planning items. Existing Core repeat-client/checklist defaults do not complete that intake-template contract. Automatic archive compaction, verified cold restoration into a replacement workbook, agency roles and a full operator/cost dashboard are also unfinished. Retained history is never deleted to make a capacity test pass. Their intended release scope must stay visible; no public page should advertise them as delivered.
