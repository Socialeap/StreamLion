# Verified archives and workbook rollover

This candidate adds signed version 2 archives and recovery into a different provider-owned workbook. It does not delete, compact or move original Google records or files. Source verification and local synthetic UI proof are separate from deployment and authorized live Google acceptance.

## Package and original files

At the end of the existing 90-day closed-job access period, the archive contains the archived job, complete coordination event chain including the final archive event, all linked project and observation revisions, a provider report and a separate client-safe HTML work order. The client report excludes provider-only fields, field observations and private attachments. The package identifies its original provider, payment mode, workbook and Drive folder. A purpose-tagged HMAC binds the entire canonical payload to that original workspace using the existing server signing key. A Drive checksum alone cannot authorize recovery.

For a closed or cancelled job, the provider may instead choose **Archive now · end client access** after recording a reason. This deliberately ends client access at verified completion and packages the exact final event/projection. It does not alter an active job or fabricate a production clock. An unverified archive retains the original operation and leaves the prior server mapping/grants unchanged until recovery completes. The normal 90-day schedule remains in place for jobs not archived early.

App-owned Drive references are verified as private provider-owned files within the selected private folder or its project subfolders. The package records byte count, type, name, SHA-256 and originating attachment/note identities. Field originals must match their stored capture checksum; new coordination uploads also store a signed byte checksum. For older uploads without that signed checksum, version 2 establishes a recovery checksum when archiving; it does not retroactively prove their original upload bytes. Recovery rechecks every manifest entry. Missing, changed, shared or misplaced originals stop recovery without discarding the source.

External HTTPS references are preserved and explicitly labelled reference-only. They are never fetched, copied or represented as backed-up originals. Device-only unsynced drafts and originals are outside the Google archive; use the existing device backup separately.

The package limit remains 700,000 encoded bytes. Verification is bounded to 40 unique Drive originals, 5 MiB per original and 25 MiB total. If a bound is exceeded, the original workbook/files remain intact for reviewed export. Large encrypted recovery journals use bounded base64 encoding while retaining the existing ciphertext format and context authentication.

## Recovery and concurrency

1. Choose another compatible StreamLion workbook in Core Connections, retain the original private Drive folder, and explicitly authorize that selected workspace's background Google access. No access or grant is created automatically by recovery.
2. Open **Archives and workbook recovery** and paste the private version 2 archive's Drive file ID or normal file link. The current provider purchase, session, origin checks and Google authorization apply. Another provider, mode or folder cannot use the archive.
3. The server verifies package signature, history chains and file identities. The original server job must still be archived with the same closure/access deadlines. An active, reopened or newer closure is rejected. Version 1 archives require review of their original workbook; already-journaled version 1 writes remain recoverable.
4. Source and destination workbook writer gates are acquired atomically using the existing durable operation table. Recovery holds both gates until verified completion. The complete signed package is encrypted in the primary operation; the source guard delegates only to that bound operation/provider/mode. No migration or new durable table is needed.
5. Project, observation, re-signed coordination event and archive-index rows are added in one atomic Sheets `appendCells` batch. [Google documents batch failure atomicity](https://developers.google.com/workspace/sheets/api/guides/batchupdate) and [appendCells appends after existing data](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/request#appendcellsrequest). No explicit write range, header rewrite, row clearing or deletion is used. Existing unrelated records are preserved. Any existing partial import, record identity conflict or newer job history requires review. An identical completed append is verified instead of repeated after a lost acknowledgement.
6. Only after full readback does one D1 transaction move the archived job's mapping to the destination, revoke old client sessions, consume old challenges and complete both journals. No project charge, invitation, email or new client grant is created. Original source rows and Drive files stay in place. The source provider list omits moved jobs from actionable requests while keeping archive pointers and original audit records.

Recovery restores the signed archive snapshot. Direct manual edits made to the original Google workbook after archiving remain there and require reconciliation; they are not silently overwritten or claimed as part of the earlier package. A different archived job may be recovered later, while an archive for a moved/reopened job is rejected. Unknown outcomes retain both locks and offer the existing **Recover original save** action. Never force-clear a pending operation to make another write proceed.

The imported job remains archived and read-only. To resume corrections, the provider must enter a reason and explicitly reopen it. Old sign-in grants remain revoked and a fresh invitation is required. Reopening preserves the existing project identity and one-time credit accounting.

## Rollover and limits

Restore readback compares every declared header column and accepts Google's omitted trailing empty cells. [Google's ValueRange contract](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values#ValueRange) excludes those blanks from output. Non-empty unexpected columns still require review. The recovery transport fixtures reproduce the trimmed response shape, including notes without a file link and project fields left blank.

Multiple provider workbook connections are already supported by the committed schema. A fresh authorized workbook can hold new requests while older client links continue to use their original job/workbook mapping. The provider can switch back to manage older requests. Closed archived jobs can be restored on demand into the new workbook rather than loading every old event into it. Templates remain in their own workbook; restored job history retains each request's pinned intake questions.

This is a non-destructive rollover. Archiving does not shrink the original workbook, and it is not a throughput guarantee. The existing 10,000-total-row per tab ceiling stays unchanged. Import preflight also reserves an encoded 7 MiB snapshot envelope beneath the adapter's existing 8 MiB response ceiling. Keep original workbooks accessible and preserve the private Drive folder; do not clear historical rows as an informal compaction method. Representative Cloudflare/Google staging workload, queue age, memory and physical-device acceptance remain separate launch gates.

## Release classification and QA

The candidate requires **Cloudflare Functions and frontend deployment** through the existing GitHub/main release path. It uses existing Google/D1 schemas, permissions and signing/encryption configuration; no migration, secret, OAuth scope, access duration, environment switch, payment setting, AI request or spend allowance is added. No Lovable action is required. Required CI and concrete owner merge approval precede release; deployment must match the merged SHA.

The full suite passed **444 tests** with no failures or skips, following **61 focused rendered/backend checks**. App/extension builds and Cloudflare Functions compilation passed. Tests cover package tampering with recalculated checksum, account/mode/folder isolation, missing signing configuration, complete event/record chains, private client handover, exact original byte identity, private Drive metadata, bounded binary reads in Node and the actual Workers runtime, atomic lost-acknowledgement recovery, partial/newer/conflicting target state, capacity denial, both workbook locks, bound guard delegation, stale/active source denial, final-transaction acknowledgement loss, unchanged recovery wallets/outbox and revoked client grants. Early archival also verifies final package history, denies active-job/client/blank-reason commands and leaves prior server grants intact when package completion is unverified.

Native local UI proof used the synthetic preview: recovered an archived job, observed read-only fields and disabled reasonless reopen, verified no expired invitation-copy control, and checked archive guidance at 390 × 844 with no horizontal overflow. The viewport was restored. These checks sent no email or Google/Stripe/AI requests. Screenshots remain local outside the repository.

After deployment, authorized synthetic Google acceptance must exercise archive generation/index readback, independent destination workbook selection/grant, restore/readback, original-file hash comparison, original source retention, expired client-grant rejection and a reasoned reopen with fresh verification. The earlier QA grant was revoked; source tests do not authorize another grant. Do not alter production deadlines or manufacture a live archive state to accelerate that test. Existing archive schedules, the test email allowance and all live launch gates remain unchanged.
